# Technical architecture of personal AI agents (state as of November 2026)

Scope note: this covers how production consumer personal agents (natural conversation, long-term memory, real-world actions like bookings) are built in late 2026. Anything from 2025 or earlier is marked as such. Many 2026 benchmark numbers are vendor self-reported; this is flagged per item. Builder context assumed throughout: a solo/small team with an existing Python agent (FastAPI runtime, memory engine, background cognition jobs, tool registry).

---

## KQ1. What does an end-to-end reference architecture for a personal agent look like (channels -> runtime -> context/memory -> model -> tools -> actions -> background jobs -> evals)?

### Takeaway
The 2026 consensus architecture is: thin channel adapters (WhatsApp/Telegram/app push) -> a stateless-per-request agent runtime that owns the loop -> a context-engineering layer (compaction, tool-result clearing, memory tool/notes) -> one frontier model with native function calling -> tools exposed via MCP or a local registry -> high-risk actions gated by confirmation -> a scheduler for proactive runs -> trace-level observability feeding offline evals. Protocols moved toward stateless, cacheable designs (MCP 2026-07-28), and the big vendors converged on "server-side context management + file-like memory tool" rather than bespoke RAG.

### Cited Findings

**Protocol/tool layer (MCP) in 2026**
- The current MCP spec is 2026-07-28. Major changes: protocol-level sessions and the `Mcp-Session-Id` header were removed from Streamable HTTP; the `initialize` handshake was removed and every request carries protocol version and client capabilities in `_meta`; a new `server/discover` RPC advertises versions and capabilities; a single long-lived `subscriptions/listen` POST stream replaces GET + `resources/subscribe` — [MCP 2026-07-28 changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog)
- Server-initiated requests (`roots/list`, `sampling/createMessage`, `elicitation/create`) were replaced by the Multi Round-Trip Requests (MRTR) pattern: the server returns `InputRequiredResult` (`resultType: "input_required"`) and the client retries the original request with `inputResponses`. All results now carry a required `resultType` — [MCP 2026-07-28 changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog)
- Tasks moved out of core into an official extension `io.modelcontextprotocol/tasks`: blocking `tasks/result` was replaced by polling `tasks/get`, `tasks/update` for client-to-server input, `tasks/list` removed; servers may return task handles unsolicited — [MCP 2026-07-28 changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog); [AAIF tasks extension post](https://aaif.io/blog/handle-long-running-mcp-tool-calls-with-the-mcp-tasks-extension)
- Roots, Sampling and Logging features are Deprecated (12-month minimum window); suggested migrations: pass paths as tool params, call LLM providers directly instead of Sampling, use stderr/OpenTelemetry for logging. HTTP+SSE transport is Deprecated in favor of Streamable HTTP. OAuth Dynamic Client Registration is deprecated in favor of Client ID Metadata Documents — [MCP 2026-07-28 changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog)
- Spec now requires `ttlMs` and `cacheScope` on `tools/list` and similar results, and recommends deterministic tool ordering "to improve LLM prompt cache hit rates"; OpenTelemetry `traceparent`/`tracestate`/`baggage` propagation in `_meta` is documented — [MCP 2026-07-28 changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog)
- The MCP roadmap says the Tasks extension is still being matured before it can move into the spec — [MCP roadmap](https://blog.modelcontextprotocol.io/posts/mcp-roadmap/)

**Context/memory layer as offered by the model vendor (Anthropic, first-party)**
- Anthropic's cookbook (March 20, 2026) documents three server-side context primitives: compaction (`compact_20260112`, beta header `compact-2026-01-12`, minimum trigger 50K tokens, default 150K, optional `instructions` and `pause_after_compaction`), tool-result clearing (`clear_tool_uses_20250919`, default trigger 100K, default `keep` 3 tool uses, `clear_at_least`, `exclude_tools`), and the memory tool (`memory_20250818`, client implements `view`, `create`, `str_replace`, `insert`, `delete`, `rename` against a file store) — [Anthropic cookbook: context engineering tools](https://platform.claude.com/cookbook/tool-use-context-engineering-context-engineering-tools)
- The memory tool auto-injects a system prompt: "ALWAYS VIEW YOUR MEMORY DIRECTORY BEFORE DOING ANYTHING ELSE... Your context window might be reset at any moment." Cookbook warns to guard path traversal and cap file/directory sizes — [Anthropic cookbook](https://platform.claude.com/cookbook/tool-use-context-engineering-context-engineering-tools)
- Illustrative (not benchmark) cookbook run on a ~329K-token corpus: no management peaked at 335,279 tokens (rejected on a 200K window after 3 turns); compaction at 180K trigger peaked at 169,164 with a ~2,783-token summary that kept 3/3 high-level facts but 0/3 obscure table values; tool-result clearing peaked at 173,137 and freed ~163K tokens per firing; with memory notes from a prior session, file reads dropped 8 -> 4 and peak context 333,977 -> 172,623 — [Anthropic cookbook](https://platform.claude.com/cookbook/tool-use-context-engineering-context-engineering-tools)
- Cost trade-offs stated qualitatively: compaction needs a summarizer inference call; clearing needs no inference but invalidates cached prefixes; memory adds tool-call overhead — [Anthropic cookbook](https://platform.claude.com/cookbook/tool-use-context-engineering-context-engineering-tools)
- Claude Code in production uses compaction for long conversations plus two complementary memory systems for cross-session persistence — [Anthropic cookbook](https://platform.claude.com/cookbook/tool-use-context-engineering-context-engineering-tools)
- A third-party tutorial mentions an `agent-memory-2026-07-22` beta header for dedicated memory stores; no corroborating Anthropic source found, treat as unverified — [search summary](https://tianpan.co/blog/2026-02-26-context-engineering-memory-compaction-tool-clearing)

**Frameworks and when each fits (practitioner comparisons, 2026)**
- LangGraph: described as the go-to for complex, stateful workflows with explicit state-machine branching, retries, human-in-the-loop checkpoints, and durable checkpointing (crash recovery); requires more upfront design than CrewAI — [Speakeasy comparison](https://www.speakeasy.com/blog/ai-agent-framework-comparison); [IoT Digital Twin PLM 2026 comparison](https://iotdigitaltwinplm.com/langgraph-vs-crewai-vs-agents-sdk-vs-pydantic-ai-2026/)
- OpenAI Agents SDK: built around handoffs and guardrails, positioned for teams committed to OpenAI models; Sessions carry history but it is "not a durable workflow engine" and does not run agents in parallel natively — [IoT Digital Twin PLM comparison](https://iotdigitaltwinplm.com/langgraph-vs-crewai-vs-pydantic-ai-agents-sdk-2026/); [Nesyona 2026 comparison](https://nesyona.com/articles/best-ai-agent-frameworks-2026)
- Pydantic AI: favored for typed, validated outputs and lightweight Python services; main gap is multi-agent orchestration (no built-in handoff lists) — [ianas.fr 2026 pick](https://ianas.fr/en/blog/2026/06/02/crewai-langchain-langgraph-comparatif-pragmatique/); [Speakeasy](https://www.speakeasy.com/blog/ai-agent-framework-comparison)
- CrewAI: role-based agent teams, fastest route to a working prototype — [ianas.fr](https://ianas.fr/en/blog/2026/06/02/crewai-langchain-langgraph-comparatif-pragmatique/)
- Claude Agent SDK is covered as a primitive reference (hooks, subagents, MCP, permissions) in a 2026 8-SDK comparison — [Morphllm 2026 framework update](https://www.morphllm.com/ai-agent-framework)
- Langfuse's open-source framework comparison (March 2025, older) is a frequently cited baseline for LangGraph/CrewAI/AutoGen/etc. — [Langfuse agent framework comparison (2025)](https://langfuse.com/blog/2025-03-19-ai-agent-comparison)
- Memory frameworks: Letta (MemGPT lineage) is an OS-analogy runtime where the model edits its own in-context memory blocks via tools, archival memory backed by PostgreSQL + pgvector; Mem0 is a memory layer beside the agent with vector + graph + key-value storage; Zep/Graphiti is a temporal knowledge graph with validity windows and bi-temporal indexing — [Atlan 2026 memory frameworks](https://atlan.com/know/best-ai-agent-memory-frameworks-2026/); [Dataaspirant Mem0 vs Letta vs Zep](https://dataaspirant.com/blog/mem0-vs-letta-vs-zep/); [Vectorize 8 memory systems](https://vectorize.io/articles/best-ai-agent-memory-systems)

### Inferences
- For the builder: the FastAPI runtime + tool registry already matches the 2026 shape. The highest-leverage adds are (a) adopting the vendor's server-side compaction/tool-result clearing instead of hand-rolled truncation, (b) exposing the existing tool registry as an MCP server (stateless 2026-07-28 style, deterministic tool ordering for cache hits), and (c) a single confirmation gate in the loop (see KQ5). A full framework migration (LangGraph etc.) is not needed; the only framework feature worth borrowing is durable checkpointing of in-flight multi-step tasks, which can be done with a Postgres table keyed by run ID.
- Standalone browser-agent products (Mariner, Operator) were consolidated into general assistants within 12-18 months; the durable pattern is "assistant that can browse when needed", not "browser agent as the product".
- Dot, Humane and Rabbit show that a companion/personal device dies when the cloud backend or company does; the product moat was never the form factor.

- Did not find primary documentation on how Mariner capabilities are exposed in the Gemini API / Vertex AI today.
- No sourced detail on LangGraph/Pydantic AI/OpenAI Agents SDK current version numbers; comparison posts disagree on versions.

## KQ2. Which memory approaches actually work for multi-month personal context, and what do benchmarks show?

### Takeaway
LoCoMo is near-saturated (88-96%, mostly self-reported) and no longer discriminates; LongMemEval and the newer BEAM (1M-10M token contexts) are the live tests. The approaches that score well in 2026 combine extraction into discrete facts, hybrid retrieval (semantic + BM25 + entity), and temporal validity tracking; benchmarks show that simple retrieval often beats elaborate hierarchies, and that recall scores do not predict whether memory improves downstream decisions.

### Cited Findings

**Benchmarks and scores (mostly vendor-reported, flagged)**
- Benchmark sizes: LoCoMo 1,540 questions; LongMemEval 500; DolphinBench 600 tasks — [Mem0 state of memory 2026](https://mem0.ai/blog/state-of-ai-agent-memory-2026)
- Mem0 self-reported (April 2026 algorithm): LoCoMo 92.5 at 6,956 tokens/query; LongMemEval 94.4 at 6,787 tokens/query; BEAM (1M tokens) 64.1; BEAM (10M tokens) 48.6, i.e. about a 25% drop when context grows 10x. Claimed gains over prior algorithm: temporal queries +29.6 points, multi-hop +23.1. Not peer-reviewed; eval framework open-sourced — [Mem0 state of memory 2026](https://mem0.ai/blog/state-of-ai-agent-memory-2026)
- Competitor figures as listed on Mem0's own page (not independent): Zep LoCoMo 80.32% at 189ms (up to 83% config-dependent), LongMemEval 71.2 (GPT-4o judge); Letta LoCoMo 74.0 (gpt-4o-mini, filesystem storage); OpenAI Memory 52.9 (flagged as needing confirmation) — [Mem0 state of memory 2026](https://mem0.ai/blog/state-of-ai-agent-memory-2026)
- Agent Zero paper reports LoCoMo 93.60%, beating Mem0 and ByteRover 2.0 (92.2%); third-party table lists Agent Zero LongMemEval 95.6% and Mastra 94.87% — [Agent Zero Memory (arXiv 2608.29606)](https://arxiv.org/pdf/2608.29606); [Mem0 benchmark roundup](https://mem0.ai/library/agent-memory/ai-memory-benchmarks-in-2026)
- Zep and ZeroMemory claim LoCoMo in the 94-96% range, self-reported; ByteRover 92.8% on LongMemEval-S — [Mem0 benchmark roundup](https://mem0.ai/library/agent-memory/ai-memory-benchmarks-in-2026)
- A 2026 arXiv paper declines to average the benchmarks into one leaderboard: LoCoMo, LongMemEval-S and BEAM "are therefore used as complementary probes of different memory behaviors" — [Eywa (arXiv 2605.30771)](https://arxiv.org/pdf/2605.30771)
- One paper argues agents near-saturated on LoCoMo "fail badly once memory must guide sequential decisions" — [Mem-T (arXiv 2601.23014)](https://arxiv.org/pdf/2601.23014)
- A cost-aware evaluation of long-term memory in tool-using agents exists (title: "When Does Memory Help?"), indicating the field now measures memory benefit net of token cost — [arXiv 2609.05441](https://arxiv.org/pdf/2609.05441)
- AgentMemBench (2026) is a systematic benchmark of memory management strategies for conversational agents; it observes Letta is "the only one whose core architecture treats memory as something an agent synthesizes during conversation rather than stores for later retrieval" — [AgentMemBench (arXiv 2608.00009)](https://arxiv.org/pdf/2608.00009)
- A 2026 paper found "comparatively simple retrieval based systems can outperform more elaborate memory hierarchies on existing benchmarks" — [Agentic Context Management (arXiv 2607.21503)](https://arxiv.org/pdf/2607.21503)
- A longitudinal evaluation paper reports a "tenure crossover" in memory-architecture rankings: which architecture wins changes with how long the agent has known the user — [Ground Truth First (arXiv 2607.21962)](https://arxiv.org/pdf/2607.21962)
- An architectural study across thirteen system configurations finds that where the memory control plane sits shapes forgetting behavior — [Control-Plane Placement Shapes Forgetting (arXiv 2606.15903)](https://arxiv.org/pdf/2606.15903)

**Architecture patterns that score**
- Mem0 2026: single-pass ADD-only extraction (agent-generated facts stored alongside user facts); retrieval via three parallel scoring passes (semantic similarity, BM25 keyword, entity matching) fused into one score; optional reranking (Cohere, HF, Sentence Transformers, or LLM); entities in a parallel `{collection}_entities` collection that boosts matches; relationships "no longer traversable", which the page calls a regression for some teams — [Mem0 state of memory 2026](https://mem0.ai/blog/state-of-ai-agent-memory-2026)
- Forgetting: Mem0 says "decay handles low-relevance memories" without describing the mechanism, and states that high-relevance stale memories remain an open problem; consolidation and reflection are not described as distinct mechanisms — [Mem0 state of memory 2026](https://mem0.ai/blog/state-of-ai-agent-memory-2026)
- Hierarchical memory (core / recall / archival tiers managed through explicit agent calls) is attributed to MemGPT/Letta — [Mem0 state of memory 2026](https://mem0.ai/blog/state-of-ai-agent-memory-2026)
- Zep/Graphiti tracks validity windows on every node and edge so an agent can answer what was true at an earlier point (temporal versioning, bi-temporal indexing); trade-off: the graph approach "requires a full inference step for each memory insertion, increasing both latency and cost" — [Atlan 2026](https://atlan.com/know/best-ai-agent-memory-frameworks-2026/); [Memanto (arXiv 2604.22085)](https://arxiv.org/pdf/2604.22085)
- Mem0 gates graph features behind its Pro tier — [Dataaspirant](https://dataaspirant.com/blog/mem0-vs-letta-vs-zep/)
- 2026 research directions: provenance-grounded memory (Eywa, Agent Zero), typed semantic memory with information-theoretic retrieval (Memanto), RL-trained memory agents with densified rewards (Mem-T), behavioral specification as an interpretive layer over recall for personalization — [Eywa](https://arxiv.org/pdf/2605.30771); [Memanto](https://arxiv.org/pdf/2604.22085); [Mem-T](https://arxiv.org/pdf/2601.23014); [Beyond Recall (arXiv 2605.28969)](https://arxiv.org/pdf/2605.28969)
- Anthropic's first-party approach is file-based notes the model edits itself (memory tool) plus compaction, with Claude Code running two complementary memory systems in production — [Anthropic cookbook](https://platform.claude.com/cookbook/tool-use-context-engineering-context-engineering-tools)

### Inferences
- For a multi-month personal agent, the evidence favors: (1) extracted atomic facts with timestamps and provenance, (2) hybrid retrieval (dense + BM25 + entity boost) rather than pure vector, (3) explicit validity windows for facts that change (job, city, relationship status), and (4) an agent-editable notes/profile file for stable identity facts. Graph traversal is optional and expensive; temporal validity is not optional.
- Benchmark saturation means a small team should build its own eval set in the LongMemEval style (facts planted months earlier, abstention cases, temporal "what was true in March" questions) and add a downstream task where memory must change a decision, since recall scores alone are shown not to predict that.
- Builder reuse: an existing memory engine can keep its store; the upgrade path is adding BM25 + entity index alongside the vector index, adding `valid_from/valid_to` to facts, and running the existing background cognition jobs as the consolidation/decay pass. None of the vendors expose a mechanism for high-relevance stale memories, so this remains a differentiator.

### Gaps
- No neutral, maintained leaderboard for LoCoMo/LongMemEval/BEAM exists as of November 2026; all cross-vendor comparisons come from interested parties.
- No sourced numbers on the actual mechanism or effectiveness of memory decay/forgetting in any production system.
- Did not find independent latency numbers for Mem0 retrieval (only Zep's 189ms, from Mem0's page).
- Did not find published results for OpenAI or Google consumer memory beyond the unverified 52.9 figure.

## KQ3. How reliable are browser/computer-use agents for real transactions in 2026, and what are the failure modes?

### Takeaway
On static desktop benchmarks the frontier is now above the human baseline (OSWorld-Verified top 90.19% vs human 72.36%), but on long live workflows (OSWorld 2.0, ~318 tool calls/task) binary completion is still below 50%, and on the live web about half of failures are environmental (loading, access blocks, CAPTCHAs). Real transactions remain high-variance: WebArena top is ~74% vs human 78%, and vendors' 97% Online-Mind2Web claims use their own judges.

### Cited Findings

**Desktop computer use**
- OSWorld-Verified (369 tasks, 100-step budget, avg ~30 tool calls): Intelligence-Indeed Agent 90.19% (2026-07-25), Claude Fable 5 85.96% (2026-08-01), Pointer Agent with Opus 4.7 83.64% (2026-05-21), Claude Opus 5 83.39% (2026-08-01), Coasty CUA v1 82.81% (2026-07-01); human baseline 72.36%; maintained by XLANG Lab HKU; Verified upgrade released July 28, 2025 — [Presenc OSWorld 2026 snapshot](https://presenc.ai/research/osworld-computer-use-leaderboard-2026)
- Conflicting figures: Steel's leaderboard shows Qwen3.8-Max at 86.1% as top with no clear source; Coasty blog posts claiming ~82-85% leadership are vendor marketing — [Steel OSWorld leaderboard](https://leaderboard.steel.dev/leaderboards/osworld/); [Coasty blog](https://coasty.ai/blog/osworld-benchmark-2026-ai-computer-use-agents-ranked)
- OSWorld 2.0 (released June 26, 2026): 108 long workflows across 31 self-hosted websites and desktop apps; median human time ~1.6 hours/task; ~318 tool calls/task; 500-step budget; scoring is binary completion plus partial score over ~27.25 checkpoints/task; vendors usually lead with partial. On v2.1 (Sept 16, 2026): Claude Opus 5.5 81.8% partial / 48.7% binary (vendor); Claude Fable 5 80.7% partial (vendor); Claude Opus 5 max effort 77.67% partial / 44.33% binary (official). Opus 5 ranges from 18.81% binary at low effort to 44.33% at max effort. Earlier: Claude Fable 5.1 77.9% partial / 41.7% binary (Sept 1, 2026); GPT-6 Astra 72.6% (offline subset, metric unstated); GPT-5.6 Sol 62.72% partial / 27.34% binary on v2026.08.08 — [Presenc OSWorld 2026 snapshot](https://presenc.ai/research/osworld-computer-use-leaderboard-2026); [Miraflow OSWorld 2.0 explainer](https://miraflow.ai/blog/osworld-2-explained-computer-use-agent-benchmark-2026)
- The v2026.08.08 update changed 14 tasks to prevent reward hacking and 31 for scoring robustness; Opus 5 rose from 31.43% to 44.33% binary between v2026.08.08 and v2.1 with no model change (benchmark drift) — [Presenc](https://presenc.ai/research/osworld-computer-use-leaderboard-2026)
- 2025 baseline for context: OpenAI CUA (Operator) launched at 38.1% OSWorld, 58.1% WebArena, 87% WebVoyager; OpenAI noted WebVoyager tasks are "relatively simple" — [OpenAI CUA (Jan 2025)](https://openai.com/index/computer-using-agent/)

**Web agents**
- WebArena: Steel's aggregation (updated June 29, 2026) lists WebTactix on DeepSeek v3.2 at 74.3% and OpAgent at 71.6%; OpAgent paper (Jan 2026) claimed SOTA at 71.6%; human baseline about 78.24%; original GPT-4 agent 14.41% (2023). WebArena-Verified (812 tasks): Muse Spark 1.1 (Meta) 69%. Scores across original/refactored/verified variants are not directly comparable — [Steel WebArena](https://leaderboard.steel.dev/leaderboards/webarena.md); [OpAgent (arXiv 2602.13559)](https://arxiv.org/html/2602.13559); [BenchLM WebArena-Verified](https://benchlm.ai/benchmarks/webArenaVerified)
- Online-Mind2Web (300 live tasks): Browser Use Cloud (bu-max) self-reported 97% in March 2026 "graded by our own agentic judge" (later pages say 98%); Steel's board lists Browser Use 97.0%, OpenAI GPT-5.4-era 93%, ABP + Claude Opus 4.6 86%; a May 2025 Browser-Use scaffold with Claude Sonnet 4 scored 40.0%. Browser Use's repo says of its 9 non-passing tasks, 2 are impossible for any browser agent and 7 are genuine failures — [Browser Use Online-Mind2Web post](https://browser-use.com/posts/online-mind2web-benchmark); [Steel Online-Mind2Web](https://leaderboard.steel.dev/leaderboards/online-mind2web/); [browser-use/online-mind2web repo](https://github.com/browser-use/online-mind2web)
- A comparison argues the 97% belongs to a managed cloud service "evaluated by the vendor with the vendor's own judge" and notes a 63.3% result for a different Browser Use setup — [Digital Applied open-source browser agents](https://www.digitalapplied.com/blog/open-source-browser-computer-use-agents-2026)
- 2025 independent table (older): Operator (GPT-4o) 61.0% on a filtered WebVoyager subset vs Browserable 90.4% and Browser Use 89.1% — [WebSight (arXiv 2508.16987)](https://arxiv.org/pdf/2508.16987)
- WAREX (Oct 2025) studies web agent reliability on existing benchmarks, i.e. variance across runs, not just mean success — [WAREX (arXiv 2510.03285)](https://arxiv.org/pdf/2510.03285)

**Failure modes**
- OpenWebRL manually reviewed 100 failed live-web trajectories: 51% access/environment issues (page loading failures, access restrictions, CAPTCHA blockers), 27% reasoning/knowledge limits (overlooking one or more constraints in multi-requirement shopping/search tasks), plus interaction errors such as clicking a nearby but incorrect element, and a small fraction attributed to judge errors — [OpenWebRL (arXiv 2606.02031)](https://arxiv.org/pdf/2606.02031)
- A vendor framework (Future AGI) lists six production failure modes that public benchmarks miss: DOM selector drift, screenshot ambiguity, login state, modal interruptions, rate-limit cliffs, irreversibility — [Future AGI](https://futureagi.com/blog/evaluating-browser-use-agents-2026/)
- Prompt injection is the dominant security failure for browser agents: Anthropic's Claude for Chrome red-team (autonomous mode, 123 cases, 29 scenarios) had a 23.6% attack success rate without mitigations, 11.2% with; a browser-specific challenge set (4 attack types) went 35.7% -> 0%; browser-specific threats include hidden DOM form fields and injections in URL text or tab titles; Anthropic states the risk "is not zero" — [Claude for Chrome (Anthropic, Aug 2025 onward)](https://claude.com/blog/claude-for-chrome)
- Real exploits: ShadowPrompt zero-click injection via a malicious page, patched January 2026; Manifold Security reported two unpatched vulnerabilities in Claude for Chrome v1.0.80 in July 2026 (secondary reports) — [Penligent ShadowPrompt writeup](https://www.penligent.ai/hackinglabs/claude-extension-prompt-injection-how-shadowprompt-turned-a-trusted-subdomain-into-a-browser-scale-risk/); [usecarly safety post](https://www.usecarly.com/blog/is-claude-in-chrome-safe/)
- A secondary blog cites Anthropic internal testing with Opus 5: 3.8% injection success before extra safeguards, zero with probes and a safety classifier; different model/test set from the 23.6% figure, not comparable — [Medium: Claude in Chrome attack data](https://medium.com/@adi_leviim/would-you-let-an-ai-click-delete-all-in-your-logged-in-browser-95abd81e2539)
- Since August 26, 2026 Claude in Chrome reportedly auto-approves actions it judges safe (same mechanism as Claude Code auto mode) and blocks actions that do not match the request; can be switched off (secondary source) — [ai-toolbox](https://www.ai-toolbox.co/claude-management-and-productivity/claude-for-chrome-setup-limits-2026)

### Inferences
- For a personal agent doing bookings: expect roughly 70-90% first-try success on well-structured sites, with half the failures outside the agent's control (CAPTCHA, bot blocks, slow loads). Design for retry, for graceful hand-back to the user ("I got to the payment page, please finish"), and for idempotency on anything that charges money.
- Prefer API/MCP integrations (OpenTable-style, Uber/DoorDash via ChatGPT Apps precedent) over browser automation wherever a partner API exists; use the browser only as a fallback. Browser automation on sites that actively block bots is a liability, not a feature.
- Builder: do not build a computer-use stack. Use a hosted browser agent (Browser Use cloud, or Claude/OpenAI computer-use tools) behind a tool in the registry, with the confirmation gate from KQ5 in front of any submit/pay step. Run it in a separate browser profile with no saved payment methods.

## KQ4. What does the voice stack look like and what latency do users tolerate?

### Takeaway
Two viable stacks in 2026: native speech-to-speech (gpt-realtime-2.1 / mini, Gemini 3.1 Flash Live, Grok Voice Agent, Nova 2.5 Sonic) with end-to-end time-to-first-response of ~0.8-1.1s measured, or a chained STT-LLM-TTS pipeline at ~1.0-1.5s but 5-10x cheaper and with full text-LLM tool calling. Human conversational response is ~200ms; nothing hosted reaches that, and the practical target is under ~1s with early turn-taking.

### Cited Findings
- Artificial Analysis end-to-end time-to-first-token (April 2026): xAI Grok Voice Agent ~0.78s; OpenAI gpt-realtime-1.5 ~0.82s; Amazon Nova 2 Sonic ~1.14s; Step-Audio R1.1 (Realtime) ~1.51s; Gemini 3.1 Flash Live ~2.98s — [Softcery real-time vs turn-based (citing Artificial Analysis)](https://softcery.com/lab/ai-voice-agents-real-time-vs-turn-based-tts-stt-architecture)
- Model-level latencies: Moshi ~160ms; Ultravox under 300ms. Telephony adds 100-200ms fixed delay; STT runs at about 0.2x real time; modern TTS reaches RTF 0.1 or better; LLM throughput examples Grok 4.1 Fast ~135 tok/s, Gemini 3.1 Flash-Lite ~314 tok/s — [Softcery](https://softcery.com/lab/ai-voice-agents-real-time-vs-turn-based-tts-stt-architecture)
- Tolerance thresholds cited: human conversational response averages about 200ms; S2S delay quoted at 200-300ms in ideal conditions; recommended end-of-turn detection after 500ms of silence and only when ASR confirms finality — [Softcery](https://softcery.com/lab/ai-voice-agents-real-time-vs-turn-based-tts-stt-architecture)
- Chained STT-LLM-TTS estimated at ~1.0-1.5s vs ~800ms for gpt-realtime; the gain is attributed to removing transcription and synthesis hops — [Forasoft Realtime API guide](https://www.forasoft.com/blog/article/openai-realtime-api-voice-agent-production-guide-2026)
- Another source puts OpenAI Realtime at ~500ms TTFB for US clients; AssemblyAI reports ~1s end-to-end — [unleashx TTS APIs](https://unleashx.ai/feeds/blog/best-apis-scalable-voice-ai-integration/); [Stream speech APIs](https://getstream.io/blog/speech-apis/)
- Current OpenAI models are gpt-realtime-2.1 and the cheaper gpt-realtime-2.1-mini (July 2026); Amazon Nova 2.5 Sonic GA October 2026 — [Stream speech APIs](https://getstream.io/blog/speech-apis/)
- Pricing: gpt-realtime-1.5 $32/1M audio-in, $64/1M audio-out (~$0.30/min baseline, $1.50+/min with long context); Gemini 3.1 Flash Live $3/1M in, $12/1M out (~$0.023/min baseline plus text tokens); Grok Voice Agent $3.00/hr input (~$0.05/min); Nova 2 Sonic ~$0.017-0.02/min; chained pipeline ~$0.15/min; self-hosted open models (Ultravox v0.7, Moshi, Kimi-Audio, Step-Audio R1.1) on H100 $1.49-2.99/hr — [Softcery](https://softcery.com/lab/ai-voice-agents-real-time-vs-turn-based-tts-stt-architecture)
- OpenAI Realtime runs about 10x a chained pipeline cost because context accumulates; Nova 2 Sonic and Gemini Flash Live approach chained pricing — [Softcery](https://softcery.com/lab/ai-voice-agents-real-time-vs-turn-based-tts-stt-architecture)
- Trade-offs: S2S can begin replying before the user finishes and preserves tone; chained pipelines lose tone/emotion in the text hop but let you swap STT/LLM/TTS independently and give the full function-calling ability of the text LLM; S2S built-in TTS is "less natural than specialized TTS"; on 8kHz PSTN audio S2S benefits shrink — [Softcery](https://softcery.com/lab/ai-voice-agents-real-time-vs-turn-based-tts-stt-architecture)
- Tool calling in S2S: all four leading providers offer native tool calling; OpenAI supports remote MCP servers and SIP dialing; xAI uses an OpenAI-Realtime-compatible schema; Nova 2 Sonic supports async tool use on Bedrock — [Softcery](https://softcery.com/lab/ai-voice-agents-real-time-vs-turn-based-tts-stt-architecture)
- Chained components named: Deepgram, Gladia (STT); GPT-5.4, Gemini 3 Flash (LLM); Cartesia Sonic-3, ElevenLabs (TTS). Phone-audio WER example: xAI Grok STT 5.0% vs ElevenLabs 12%, Deepgram 13.5%, AssemblyAI 21.3% — [Softcery](https://softcery.com/lab/ai-voice-agents-real-time-vs-turn-based-tts-stt-architecture)
- Research: full-duplex speech models need a frontend-backend split to handle tool calls (arXiv 2609.19334); VoxServe is a streaming-centric serving system for speech LMs — [arXiv 2609.19334](https://arxiv.org/pdf/2609.19334); [VoxServe (arXiv 2602.00269)](https://arxiv.org/pdf/2602.00269)
- Voice task benchmarks: tau3-bench adds full-duplex voice; multilingual voice board (one trial per task) tops at Ava Zero 86.0%, Phonic-1 83.2%, gpt-live-1 79.9%; Sierra's tau-voice review of 91 failed calls attributed 79-90% of failures to agent behavior — [Cekura tau-bench explainer](https://www.cekura.ai/blogs/tau-bench)

### Inferences
- For a text-first personal agent adding voice, the chained pipeline is the right first step: it reuses the existing text agent, tool registry and memory unchanged, costs ~$0.15/min, and lands at 1-1.5s latency. Move to S2S only for a dedicated live-conversation mode, and then to Gemini Flash Live or Nova Sonic on cost unless OpenAI's quality is required.
- Latency budget to aim for: first audible response under 1s; stream TTS from the first sentence; use 500ms silence + ASR finality for end-of-turn; prefer backchannel fillers over silence beyond ~1s.

- Release dates for the Grok API conflict across sources (Oct 2026 vs Dec 2025).

## KQ5. How do production agents handle confirmations, payments and irreversible actions safely?

### Takeaway
The pattern that shipped in 2026 is layered: per-site/per-tool permissions, model-side classifiers on both inbound content and outbound actions, mandatory confirmation before publish/purchase/share-personal-data, and for payments a move to cryptographically signed mandates (Google AP2 v0.2, SD-JWT) with scoped credentials (Mastercard Agent Pay, Visa Trusted Agent). OpenAI's in-chat Instant Checkout was retired in March 2026 in favor of redirect-to-merchant, which signals that fully agent-completed payments are not yet trusted at consumer scale.

### Cited Findings

**Confirmations and permissions (Anthropic as the documented example)**
- Claude for Chrome: site-level permissions (grant/revoke per site), Claude asks before high-risk actions "such as publishing, purchasing, or sharing personal data"; experimental autonomous mode keeps safeguards for highly sensitive actions; financial services, adult and pirated-content sites blocked by default; Teams/Enterprise admins can set org-wide allow/blocklists (Dec 2025) — [Claude for Chrome](https://claude.com/blog/claude-for-chrome)
- Two classifiers: one screens incoming page content for injection, one checks each action before it runs; auto-approval of safe actions on by default since Aug 26, 2026 (secondary) — [ai-toolbox](https://www.ai-toolbox.co/claude-management-and-productivity/claude-for-chrome-setup-limits-2026)
- Anthropic recommends a separate browser profile and avoiding financial, legal, medical or other sensitive sites — [Claude for Chrome](https://claude.com/blog/claude-for-chrome)
- MCP 2026-07-28 formalizes the "ask the user mid-tool-call" flow as MRTR: a tool returns `input_required` with `inputRequests`, the client collects the answer (e.g., a confirmation) and retries; servers correlate across retries via `requestState` — [MCP changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog)

**Payments: protocols**
- Google AP2 published September 16, 2025 with 60+ launch partners; v0.2 adds SD-JWT verifiable credentials; donated to the FIDO Alliance on April 29, 2026 along with a "human not present" mandate; an August 2026 working group chaired by CVS Health, Google and OpenAI covers agent authentication, with Mastercard contributing Verifiable Intent — [eco.com AP2 explainer](https://eco.com/support/en/articles/15192002-ap2-protocol-explained-google-s-agentic-commerce-standard-2026); [agenticplug state of agentic commerce](https://agenticplug.ai/current-state-of-agentic-commerce)
- AP2 mandate mechanics (v0.2): Checkout Mandate (closed = one finalized checkout; open = constraints such as allowed merchants and acceptable line items/quantities) and Payment Mandate (bound to the same checkout; open form holds standing spend limits: budget, amount range, allowed payees, allowed instruments, execution date range, recurrence frequency and max occurrences). Merchant signs a Checkout JWT with exact line items/prices/totals; the closed mandate binds via `checkout_hash` so the merchant cannot alter it after the user signs; in Autonomous mode the open Payment Mandate pins the agent's public key and the `cnf` claim ties agent-signed closed mandates back to the user-approved open mandate; a non-agentic "Trusted Surface" renders mandates to the user; signed Checkout Receipt and Payment Receipt close the loop — [eco.com AP2 explainer](https://eco.com/support/en/articles/15192002-ap2-protocol-explained-google-s-agentic-commerce-standard-2026)
- AP2 participants: Mastercard, American Express, PayPal, Adyen, Worldpay, Coinbase, MetaMask, Salesforce, ServiceNow, Intuit, Etsy, Lowe's; roles: Shopping Agent, Trusted Surface, Merchant, Credential Provider, Network, Merchant Payment Processor — [eco.com AP2 explainer](https://eco.com/support/en/articles/15192002-ap2-protocol-explained-google-s-agentic-commerce-standard-2026)
- Mastercard Agent Pay (announced April 2025) is the first major network to enable all US cardholders for agent-initiated payments; credentials are scoped to a specific AI agent and a specific commerce policy. Visa Trusted Agent announced October 2025. Both are card-rail schemes — [eco.com Agent Pay](https://eco.com/support/en/articles/15192001-what-is-mastercard-agent-pay-ai-agent-commerce-protocol-in-2026); [eco.com AP2](https://eco.com/support/en/articles/15192002-ap2-protocol-explained-google-s-agentic-commerce-standard-2026)
- OpenAI + Stripe Agentic Commerce Protocol (ACP) published September 29, 2025 with Instant Checkout in ChatGPT; Instant Checkout was wound down in March 2026 in favor of discovery-and-redirect (buy on merchant site); ACP continued (latest stable spec 2026-04-17) and now powers ChatGPT Apps commerce (Target, DoorDash, Instacart, Uber); OpenAI reportedly charged merchants 4% during Jan-Mar 2026 — [Stripe newsroom (launch)](https://stripe.com/en-at/newsroom/news/stripe-openai-instant-checkout); [ecomcrew](https://www.ecomcrew.com/openai-pulls-back-on-chatgpt-instant-checkout/); [Forkast](https://forkast.news/openai-built-in-chat-checkout-for-ai-commerce-five-months-later-it-walked-away/); [eco.com ACP](https://eco.com/support/en/articles/14845478-acp-agentic-commerce-protocol-explained)
- Machine-to-machine rails: Coinbase x402 and Stripe's Machine Payments Protocol (MPP, launched March 18, 2026) handle onchain agent payments — [eco.com agentic commerce guide](https://eco.com/support/en/articles/14839400-what-is-agentic-commerce-the-2026-guide)

**Benchmarks that test policy compliance**
- tau-bench's reward of 1 is "necessary but not sufficient": an agent can issue a return without the user's explicit confirmation, break policy, and still be rewarded; pass^k (probability of succeeding on all k trials) exposes flakiness: GPT-4o retail pass^1 61.2% fell to under 25% at pass^8 (2024). tau3-bench banking (97 tasks, 698 policy documents): Qwen 3.8 Max 55.2% pass^1, Claude Opus 5 48.7% pass^1 dropping to 32.0% at pass^4 — [Cekura tau-bench explainer](https://www.cekura.ai/blogs/tau-bench)

### Inferences
- Minimum viable safety model for a small team: (1) classify every tool as read / reversible-write / irreversible-write / financial at registration time; (2) irreversible and financial tools always return `input_required` and need an explicit user confirmation that quotes amount, payee and what happens; (3) per-user spend caps and per-day action caps stored server-side, not in the prompt; (4) idempotency keys on every write tool; (5) run browser actions in an isolated profile with no stored payment methods; (6) log the full action trace for audit.
- Do not implement card payments yourself. Route to merchant checkout (the model OpenAI fell back to) or wait for AP2/Agent Pay availability in your market; the mandate structure (open mandate with budget, payees, recurrence) is a good template for your own internal "standing permission" object even before using the protocol.

### Gaps
- No primary OpenAI source for why Instant Checkout was retired; reasons are from secondary coverage.
- Could not confirm AP2 v0.2 release date or the current status of the FIDO working group from primary sources.
- No published data on how often consumer agents' confirmation prompts are accepted vs abandoned, or on fraud/chargeback rates for agent-initiated payments.
- Anthropic's classifier deployment status: the Claude for Chrome page says detectors are "being built and tested", while 2026 secondary sources say two classifiers are live; unresolved.

## KQ6. What eval and observability setup lets a small team iterate fast on agent quality?

### Takeaway
The 2026 toolchain is: OpenTelemetry-style traces of every run (Langfuse if self-hosting, LangSmith if on LangGraph, Braintrust if evals-first), a small curated dataset of real traces turned into regression tests, LLM-judge scorers for open-ended quality plus deterministic checks for tool/policy correctness, pass^k-style repeated runs to measure flakiness, and cost tracked per task. - Voice: VoiceAgentBench, BFCL v3 and tau-bench cited as the tool-calling reliability references for voice agents — [Softcery](https://softcery.com/lab/ai-voice-agents-real-time-vs-turn-based-tts-stt-architecture)

- LangSmith: best fit for LangChain/LangGraph stacks; full conversation and agent-run traces exposing every step, tool call and intermediate state; automated failure clustering ("Engine") — [agentopsguide comparison](https://agentopsguide.com/langfuse-vs-langsmith-vs-braintrust/); [MarkTechPost Aug 2026 roundup](https://www.marktechpost.com/2026/08/09/top-llm-observability-and-evaluation-platforms-in-2026-langfuse-langsmith-braintrust-arize-and-more-compared/)

- Braintrust: most eval-centric; "Loop" agent analyzes traces to suggest prompts, generate scorers and build datasets; generous free tier; CI/CD gating is a differentiator but a team must wire the CI job, comparison and threshold itself — [qaskills](https://qaskills.sh/blog/braintrust-vs-langfuse); [Latitude agent-first guide (competitor-authored)](https://latitude.so/blog/agent-first-comparison-guide-vs-braintrust)
- Decision rule repeated across sources: LangSmith for LangChain-heavy stacks, Langfuse for self-hosting/open-source control, Braintrust for eval-driven workflows; sources disagree on whether LangSmith/Langfuse can gate CI — [agentopsguide](https://agentopsguide.com/langfuse-vs-langsmith-vs-braintrust/); [Brainforge](https://brainforge.ai/resources/langsmith-vs-braintrust-vs-langfuse/)
- MCP 2026-07-28 standardizes OpenTelemetry trace-context propagation (`traceparent`, `tracestate`, `baggage`) in `_meta`, so tool servers can join the agent's trace — [MCP changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog)
- Anthropic's context-management API returns `context_management.applied_edits` with `cleared_tool_uses` and `cleared_input_tokens` per response, giving a direct hook for logging context-budget behavior — [Anthropic cookbook](https://platform.claude.com/cookbook/tool-use-context-engineering-context-engineering-tools)

**Eval methodology lessons from the benchmarks**
- Judge error is a real noise source: OpenWebRL attributes a small fraction of "failures" to judge errors; Browser Use's 97% uses its own agentic judge — [OpenWebRL](https://arxiv.org/pdf/2606.02031); [Browser Use](https://browser-use.com/posts/online-mind2web-benchmark)
- Simulated users add variance (interrupt timing changes between trials) but Sierra's review attributes 79-90% of failed voice calls to agent behavior, not the simulator — [Cekura](https://www.cekura.ai/blogs/tau-bench)
- pass^k: report consistency, not just mean success; tau-bench shows large pass^1 to pass^k drops (61.2% -> <25% at k=8 in 2024; 48.7% -> 32.0% at k=4 for Opus 5 on banking in 2026) — [Cekura](https://www.cekura.ai/blogs/tau-bench)

### Inferences
- Setup for a solo/small team with a Python/FastAPI agent: self-host Langfuse (or use its cloud free tier), instrument the loop so each run is one trace with spans per model call, tool call, memory retrieval and confirmation; tag traces with user, channel, model version and cost. Promote 50-200 real traces into a dataset; write deterministic scorers for tool correctness, policy adherence (did it confirm before an irreversible action), memory recall of planted facts, and latency; add one LLM-judge scorer for tone/helpfulness with a small human-labelled calibration set. Run each eval case 3-5 times and report pass^k. Gate prompt/model changes on this in CI.
- Reuse: the existing background cognition jobs can double as nightly eval runs (replay yesterday's traces against the new prompt). Build: the dataset, scorers, and the confirmation-policy checker; these are product-specific and nothing off the shelf covers them.

- No independent head-to-head benchmark of Langfuse vs LangSmith vs Braintrust (all comparisons are vendor or affiliate authored); pricing not captured.
- No published data on how large an eval dataset a consumer agent team needs before judge scores stabilize.

## KQ7. Proactive/scheduled behavior and multi-channel delivery: what are the platform constraints?

### Takeaway
Proactive behavior in 2026 means server-side scheduled or event-triggered runs that push results to the user; mobile OSes do not allow background agent loops. ChatGPT consolidated on Scheduled Tasks (hourly minimum, Gmail/Slack/GitHub triggers) after killing Pulse; WhatsApp now charges for in-window service messages beyond 1,000/month per number; Telegram caps bots at ~30 msg/s global and ~1 msg/s per chat.

### Cited Findings

**Proactive and scheduled**
- OpenAI retired ChatGPT Pulse (an overnight-research feed with morning cards) in June 2026 (release notes June 17, 2026; Pro users kept it 14 more days) and folded it into Scheduled Tasks, which has a sidebar hub and can run as often as once per hour; since late August 2026 tasks can be event-triggered by a new Gmail message, a new Slack channel message or GitHub PR activity — [usecarly ChatGPT scheduled tasks](https://www.usecarly.com/blog/chatgpt-scheduled-tasks/); [prowlo Pulse shutdown](https://prowlo.com/blog/chatgpt-pulse-shut-down); [Analytics Insight](https://www.analyticsinsight.ae/news/openai-shifts-from-ai-briefings-to-automation-with-scheduled-tasks-rollout)
- Anthropic has been rolling out scheduled tasks on Claude.ai (reported for Pro subscribers), described as limited vs ChatGPT's; a proactive assistant codenamed "Orbit" connecting Gmail/Slack/GitHub was reported from app-code leaks (TestingCatalog), unconfirmed — [MindStudio automations comparison](https://www.mindstudio.ai/blog/ai-agent-automations-claude-chatgpt-grok-comparison); [PCWorld proactive AI](https://www.pcworld.com/article/3131926/personal-ai-assistants-were-big-proactive-ai-could-be-bigger.html)
- MCP's tasks extension supports long-running tool calls via polling (`tasks/get`) and unsolicited task handles, which is the protocol-level hook for deferred/background work — [MCP changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog)

**Mobile OS limits**
- iOS background execution is opportunistic and not guaranteed; the system decides when/whether BGTaskScheduler work runs; iOS does not allow continuous background execution for arbitrary code such as polling; BGAppRefreshTask is for quick updates of roughly 30 seconds (secondary sources, not Apple's wording); AppRefresh may run within ~30 minutes of submission while the app is in memory — [AppsOnAir iOS background limits](https://www.appsonair.com/blogs/background-execution-limits-in-ios-what-every-developer-must-know); [Sheldon Wang iOS background processing (2025)](https://sheldonwangrjt.github.io/posts/2025/06/ios-background-processing)
- iOS 26 adds BGContinuedProcessingTask for work the user explicitly starts (e.g., a button tap) — [DEV: WWDC 2025 iOS 26 background APIs](https://dev.to/arshtechpro/wwdc-2025-ios-26-background-apis-explained-bgcontinuedprocessingtask-changes-everything-9b5)
- Apple's BGTaskScheduler documentation is the authoritative source; concrete limits for push-woken execution were not found — [Apple BGTaskScheduler docs](https://developer.apple.com/documentation/backgroundtasks/bgtaskscheduler.md)

**Messaging channels**
- WhatsApp Business API: Meta charges per delivered message by category and recipient country plus provider markup; from October 1, 2026 free-form service replies inside the 24-hour customer window are no longer free beyond 1,000 free service messages per business number per month (reported by partners), charged at the market's utility rate thereafter; example rates: US utility/authentication ~$0.0034-0.004, US marketing ~$0.025, Germany marketing ~$0.1365; provider fees e.g. Twilio +$0.005/msg, Gupshup +$0.001/msg — [DragApp WhatsApp pricing Oct 2026](https://www.dragapp.com/blog/whatsapp-business-api-pricing/); [eesel WhatsApp pricing](https://www.eesel.ai/blog/whatsapp-business-api-pricing); [Blueticks](https://blueticks.co/blog/whatsapp-business-api-pricing-2026)
- Telegram Bot API: about 30 messages/second global cap for bulk notifications; avoid more than 1 message/second per chat and 20 messages/minute per group; exceeding returns HTTP 429; limits are per bot account; paid broadcasts raise the cap to 1,000 msg/s at 0.1 Stars per message above the free amount — [python-telegram-bot wiki: flood limits](https://github.com/python-telegram-bot/python-telegram-bot/wiki/Avoiding-flood-limits); [SleekFlow Telegram API](https://sleekflow.io/en-gb/blog/telegram-api)

### Inferences
- Proactive behavior must live on the server: a cron/scheduler (APScheduler/Celery beat/Postgres-backed queue) runs the agent for a user, and results go out via WhatsApp template/service message, Telegram bot message, or APNs/FCM push that deep-links into the app. The existing background cognition jobs are already the right place; the add is a per-user trigger table (cron expression or event source) and a quiet-hours/frequency policy.
- Channel cost model after October 2026: WhatsApp proactive messages cost real money per message (template rates), so proactive nudges should be batched and capped; Telegram is free but rate-limited; owned app push is free but requires the app installed and notifications allowed.
- Hourly is the de-facto minimum schedule granularity consumers see (ChatGPT); event triggers (new email/message) are the next expectation.

- Apple's own current numbers for background durations and push-wake budgets were not retrieved.
- No source found on Discord bot constraints specific to agents, or on Android background limits (Doze/App Standby) in 2026.
- Anthropic's scheduled tasks rollout details and plan availability unconfirmed from primary sources.
